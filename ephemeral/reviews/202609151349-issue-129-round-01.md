## Findings

### 1. [issue] Switching output modes can silently delete another generator's file

`internal/builder/gen_schema.go:1818-1844` writes the newly selected filename and then removes the opposite filename whenever `ast.IsGenerated` returns true. `ast.IsGenerated` recognizes the standard generic `Code generated ... DO NOT EDIT.` convention; it does not prove that polytype owns the file. Consequently, the new mode-switch cleanup can delete an artifact produced by another generator.

Concrete reproduction from a scratch copy of `codegen/testdata/recursive_declarations`:

1. Add `noarg/jsonschema_gen.go` containing:

   ```go
   // Code generated by some-other-tool. DO NOT EDIT.

   package noarg

   const OtherToolOutput = "keep me"
   ```

2. Run `TARGET=noarg go run ./gen`.
3. The command exits 0 and reports `OK`, creates `polytype_gen.go`, and deletes `jsonschema_gen.go`. Its pre-run SHA-256 was `3762bf97bd2cf944a3d3db3fc81b58ecd0bebe62e93643fb5595c4f7b948be4a`; afterward the file is missing.

This is destructive behavior introduced by Defect 5's filename change and violates the requested correct outcome. Check the exact polytype ownership header before removal (and preflight removal before writing the replacement), then cover both a polytype-owned stale file and an unrelated generated file.
