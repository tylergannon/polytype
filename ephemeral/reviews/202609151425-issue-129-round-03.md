## Findings

No findings.

Round 2 finding 1 is not retained. Its requested remedy would have made
`codegen.Gen` ignore the target package's build-tagged `SealedUnion` contract.
That would silently restore the default `"type"`/Pascal wire format where the
package declares a custom discriminator, contrary to the README and godoc and
to the behavior at `dafd00d`. It would also make a dependency interface's
custom discriminator unreachable because programmatic configuration rejects a
sealed union outside the target package. The current implementation keeps the
source contract, applies executable overrides afterward, and ignores ordinary
executable configuration values during AST declaration scanning. Invalid and
duplicate build-tagged declarations correctly remain errors.

Round 2 finding 2 is resolved. Declaration-file eligibility is now checked
before dispatching every recognized call, so direct `Declare`, direct
`SealedUnion`, `Compose`, and other polytype calls in ordinary Go files neither
join CLI roots nor alter union settings. The regression includes all three
ordinary executable forms and an arbitrary runtime inflector.

The round-1 findings also remain resolved: opposite-name cleanup requires
polytype's exact generated header, and the exact issue fixture exercises Go
JSON and devalue round trips plus strict TypeScript compilation and configured
discriminator output.
