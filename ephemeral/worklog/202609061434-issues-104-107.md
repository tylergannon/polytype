decision: the generated `MarshalJSON` writes a per-member literal (`return []byte("4"), nil`) rather than converting the receiver and delegating to `json.Marshal`. That shape is rejected today only when a schema actually reaches the type, and this step must not turn it into a hard failure.

## Milestone 3, codec backend (2026-09-06)

Decisions the brief and the addenda left to the implementer:

**Object nodes are supported only as a definition's own type.** `typ()` does
lower a nested anonymous `struct{...}` field to an inline `*Object`, so the
node kind is reachable. Emitting a decoder for one means spelling that Go
type in another package, and struct tags are part of struct type identity:
a reconstructed `struct{ Text string \`json:"text"\` }` is a *different* type
from the source's if the source tag carried anything else, and the mismatch
surfaces as a compile error in generated code rather than a diagnostic. The
emitter refuses the shape instead, with the reason, and `goType` is total
over every other node. Anonymous struct roots were already refused upstream
by #104's admission boundary.

**Diagnostic paths are Go expressions, not bindings.** The first cut bound
`atN := at + "/label"` per property, mirroring the TypeScript backend's
threaded `at`. Scalars never report a diagnostic, so every such binding was
an unused variable and the generated file did not compile. Inlining the
concatenation removes the failure mode entirely: an unused path costs
nothing because it is never emitted.

**Collection loops drop an unused index.** Same class of failure one level
down -- `for i, item := range` over `[]string` leaves `i` unused. The body is
rendered into a branched emitter that continues the parent's name numbering,
then the header is written with `_` when a word-boundary search of the body
does not find the index. This is the only place the emitter inspects its own
output; the alternative (`_ = i` after every loop header) puts noise in every
generated collection.

**Union payloads.** `dvTagged` rebuilds the variant's object with the
discriminator first and drops any value the variant itself wrote under that
key, so the tag on the wire is always the resolved one. On the way back, a
variant that does not declare the discriminator as a property is handed a
copy without it (`dvWithout`), because its decoder rejects unknown
properties; a variant that does declare it gets the object unchanged and
decodes the tag as an ordinary field. Which of the two applies is decided at
generation time from the variant definition, not at runtime.

**Enum membership compares values, not constant identifiers.**
`EnumMember.Name` is a Go constant name that may be unexported, and the
emitted file lives in another package. Cases are `v == pkg.Priority(5)`, and
the switch is `switch { case ... }` rather than `switch v { case ... }` so
two constants sharing a value do not become a duplicate-case compile error.

**Numeric decode bounds are float64.** Every wire number is one, so an
`int64` field is range-checked against the rounded bound. That is exactly the
precision the encoder has -- it converts through `float64` itself -- so the
two sides agree, and the package doc says values beyond 2^53 lose precision.

Proof: `devalue/codegen/testdata/fixture` is one module with a `model`
package covering every node kind and a `codec` package holding the
assertions. The test copies it to `t.TempDir()`, rewrites the replace
directive to an absolute repo path, lowers it through `grammar.Load`/`Lower`,
writes the generated file into `codec/`, and runs `go mod tidy`, `go build`
and `go test` there. Compiling in a package that is not the declaring one is
the proof that only exported fields are touched. A second assertion walks the
lowered graph and fails if the fixture stops covering a constructor, so the
compile-and-run proof cannot silently narrow.
