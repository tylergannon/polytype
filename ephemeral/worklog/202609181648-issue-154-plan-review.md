# Issue 154 plan and adversarial review

correction: Invalid Go string and lone-surrogate behavior must not become an
unrequested subproject; preserve current Polytype behavior unless an executable
consumer or upstream case proves a user-visible defect, and explicitly account
for skgo fixtures that only snapshot invalid JavaScript bytes.

decision: `asFloat`, `formatNumber`, `maxArrayIndex`, `isArrayIndexString`, and
`propertyOrder` are functionally identical in Polytype and skgo, so issue 154
will reuse the existing Polytype implementations rather than carry duplicates.

decision: Keep flat value identity and Uneval reference counting as separately
named policies because they answer different semantic questions, while sharing
low-level key representations where safe.

decision: Keep goja execution tests in the primary module. A synthetic consumer
importing `polytype/devalue` built with an empty module cache and network disabled
without downloading any module source even when the Polytype module required
goja; a nested test module would instead fall outside the mandated
`go test ./...` gate.

correction: Adversarial-review findings are not automatically accepted. Require
an issue contract, existing consumer need, concrete executable failure, or
pinned-upstream contradiction; reject hypothetical edge-case machinery and
adjacent hardening that would delay publishing the working serializer.

friction: A repository-wide external Fable handoff was rejected because it
would expose the complete worktree and instructions -> use an isolated packet
containing only the public issue, plan, and authoritative conversation context.

decision: Fable 5.1 review session 6499f620-406c-417d-85dc-4b106afa9ba3
demonstrated that the pinned-upstream check was optional in the first plan,
skgo's goja skip claims were stale, durable docs would contradict the new API,
and repeated TypedArray values break Set identity. Accept those bounded fixes;
reject diagnostic-path escaping as non-material.

proof: Final `go test -count=1 ./...` passed after the reviewed plan and review
artifacts were written. Branch: `codex/issue-154-plan-review`; implementation
has not begun.

decision: The implementation reuses Polytype's existing number, property-order,
and string-literal helpers; only Uneval-specific identifier, reference, typed
array, and rendering logic was harvested from skgo.

decision: Five raw WTF-8 lone-surrogate snapshots were excluded from the
migrated suite because they emit invalid UTF-8 JavaScript. Valid surrogate-pair,
control-character, script-escaping, and U+2028/U+2029 cases still execute.

decision: The pinned devalue 5.9.2 recorder now stores both flat `stringify`
and `uneval` output for 324 values, including explicit shared-reference,
self-cycle, and sparse-array cases. Go parses each flat value and compares its
Uneval expression to the recorded upstream expression.

decision: goja's pinned runtime executes BigInt, boxed BigInt, BigInt typed
arrays, and custom-replacer cases. Only URL, URLSearchParams, and Temporal
fixtures remain named skips; the suite requires exactly 91 fixture executions.

friction: Go commands began failing under the filesystem sandbox when the Go
build cache needed new entries after adding goja -> rerun only the affected Go
commands with build-cache access rather than changing the repository setup.

decision: Fable 5.1 implementation review session
`54d352c5-3827-4f44-8b38-74831a7ec496` supplied two material reproductions:
free-form BigInt/RegExp metadata could inject JavaScript through Parse->Uneval,
and unhashable custom values could panic before reaching a replacer. Both were
accepted and fixed, along with the same bounded constructor-kind injection for
Temporal and typed arrays.

decision: The review's value-identity finding was handled as a documentation
boundary, not an API redesign. Go value representations cannot distinguish
equal-but-separate JavaScript reference objects; changing those public types
would violate the import-rewrite goal.

decision: The pinned recorder gained a small curated set of flat-supported
special values because issue 154 explicitly requires upstream checking for
them. No new ledger or proof infrastructure was added.

proof: After adjudicating review findings, `go test -count=1 ./...`,
`just build-tagged`, and `just lint` passed. Re-running both golden generators
left `values.mjs` and the 337-case `golden.json` byte-identical. Review and
adjudication are stored under `ephemeral/reviews/202609181726-*`. Branch:
`codex/issue-154-plan-review`.
