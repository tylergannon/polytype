## Outcome 1: JSDoc projection library

decision: Added `javascript/generate.go` (public API, projector, identifier allocation copied verbatim from the TypeScript backend so `Result.Names` matches) and `javascript/jsdoc.go` (JSDoc-only type-expression AST, printer, comment sanitizer). No barrel option: a JSDoc typedef is not a runtime binding, so an ESM barrel cannot re-export it. The CLI and `typescript/` are untouched.
decision: Object definitions use `@typedef {Object}` plus `@property` when every JSON key is a JSDoc-spellable name (identifier chars, hyphens, Unicode letters). When any key is not (quotes, whitespace, newlines, brackets, punctuation), the whole definition falls back to one inline object type (`@typedef {{...}} Name`) with JSON-quoted keys so pathological names still type-check; per-property JSDoc is not representable in that fallback.
correction: tsc rejects quoted/bracketed `@property` names (`@property {string} "kind-key"` is TS1003), so the TypeScript edge graph's `kind"\n雪` discriminator/property must use the inline-object fallback rather than a `@property` tag.
proof: baseline `go test ./...` passed before editing (all packages ok).
proof: `go test ./...` after the change passes; new `javascript` package covers complete grammar, recursion, mutual recursion, edge escaping, collision names, empty definitions, inexact numeric rejection, validation-before-projection, and `Provided` refusal. `TestGenerateMatchesTypeScriptAcceptance` runs `typescript.Generate` and `javascript.Generate` over the same five definition sets and asserts equal `Names` and no runtime exports.

## Outcome 2: CLI JavaScript output lifecycle

decision: Factored the preflight/plan/apply machinery out of `internal/builder/typescript_output.go` into a generic `internal/builder/output_plan.go` (`plannedOutputFile`, `outputPlan`, `prepareOutputPlan`, `apply`, `writeOutputFile`). `prepareTypeScriptOutput` is now a thin wrapper, so its tests and error text ("TypeScript output") are unchanged. `internal/builder/javascript_output.go` adds `prepareJavaScriptOutput` and the fixed `types.js` name.
decision: Ownership is decided by the generated header plus the fixed Polytype names (`types.js`, `types.ts`, `index.ts`). In each mode the names not produced by that mode are "obsolete candidates": a header-owned candidate is planned for removal, a headerless one is left alone. This makes mode switching symmetric without a shared-directory write.
decision: The CLI gains `--javascript DIR` and `BuilderArgs.JavaScriptDir`. Both modes reuse `TypeDefinitions()` (one lowering) and both plans are prepared before `RenderSchemas`/`RenderGoCode`/`apply`, so an unsupported shape or unowned collision writes nothing. `--javascript` has no barrel; `--typescript-barrel` stays TypeScript-only.
decision: Same-directory conflict is rejected in `validateDeclarationOutputArgs` by comparing `filepath.Abs`+`Clean` of the two directories. Rejection happens in both `Run` and `RunLoaded`, before any load or write. Distinct directories (including nested) are allowed.
