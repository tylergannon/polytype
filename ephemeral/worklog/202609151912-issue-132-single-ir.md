# Issue 132: project JSON Schema and Go codecs from typegrammar

Branch: claude/issue-132-dual-ir-e95a19. Baseline `go test ./...` green at 8b1ac72 (41 s wall).

## Decisions

decision: One PR, schema and codecs together. User rejected a two-PR split (2026-09-15): a half-way state keeps the second scan walk, which is the actual duplication.
decision: Provider fields and explicit `jsonschema:"ref="` tags enter the IR as a new `typegrammar.Provided` field form (no Type; Ref string; Optional bool). TypeScript and devalue refuse it by name. The grammar doc's "no opaque-provider constructor" sentence is amended, not violated: Provided is explicit and carries no permissive shape.
decision: Lowering is permissive once per run and records "strict notes" (the exact error strict mode would raise) instead of failing: custom wire types (MarshalJSON etc.), Provided fields, interface roots. `TypeDefinitions`/`LowerRoots`/`grammar.Lower` return notes[0] (strict, same wording and order as before). The schema and codec projections ignore notes. Reason: fixtures union_codec and v1_interfaces_options carry hand-written marshalers that the strict lowerer refuses but the schema renders structurally; entrypoints fixture has a sealed-interface root rendered as a union.
decision: Interface roots become `Union` roots for the schema projection (Union is field-only in the grammar; the projection accepts a root that is either a Name or a Union).
decision: Owner codecs are emitted only for local object definitions reachable from roots over Ref and union-variant edges. A definition reached only through embedding gets none; its union fields are promoted into the embedding owner's codec. This matches today's schema-mode behavior; today's codec-only mode over-generated and then rejected the shape.
decision: Union helper identity hashes the *raw* discriminator override ("" for default) to keep generated helper names byte-identical. The raw override is a package fact passed into codec planning, since the IR carries only the effective name. Candidate cleanup later: hash the effective name and accept the rename.
decision: Recursion is detected in the schema projection with an active set over definition names and union interface names, mirroring the old `seen` semantics. The projection returns a typed error; the builder formats the message with the package *name* as before.
decision: JSON Schema node types and the hardline printer move from internal/builder/model.go + schema_hardlines.go into the projection package as its output AST (the role typescript/ast.go plays). Byte-identical output follows from reusing the marshalers.

## Decisions (continued, after context compaction)

Reason: test6-providers' tagged schema.go duplicates provider funcs, so the package never type-checks, and the schema path never depended on go/types. `TypeDefinitions` still fails with "has type-check errors".
decision: `[]byte` fields are refused for every output (Validate: "byte-like slices have a base64 wire mapping outside this grammar"). Previously JSON Schema rendered them as an integer array, which was wrong for encoding/json's base64. No fixture or example had one.
decision: Pointer embedding is refused up front by lowering ("bare pointer field ... is not admitted"); codegen's recursive_embed proof program now expects that message instead of "competing MarshalJSON".
decision: `TypeDefinitions` reuses the one lowering unless `NewForTypes` selected a subset of roots, in which case it re-lowers all roots (grammar_test.go's lowerField relies on seeing every declared root).
decision: Strict TestBasic harness walks the fixture: every `*.golden` must have a generated counterpart and every generated artifact (`jsonschema/*.json`, `*.json.tmpl`, `jsonschema_gen.go`/`polytype_gen.go`) must have a golden. ## Review round 1 (adversarial subagent; report under scratchpad review/)

correction: the earlier worklog claim that HEAD rendered `[]byte` as an integer array in JSON Schema was wrong; HEAD schema roots failed with "type byte not found". Only codec-only roots (`Declare[T]()`) accepted `[]byte` at HEAD.
decision: Fixed — provider lookup now applies only to named owners (`c.namedOwner`); an inline struct reuses the enclosing type's name and previously matched its providers (HEAD leaked the hole into the inline field too). Explicit `jsonschema:"ref="` tags inside inline structs are admitted again: Validate requires a named owner only for provider holes (`Provided{Ref: ""}`).
decision: Refused with an honest diagnostic — a promoted field shadowed by a shallower field of the same Go name but a different JSON name (`Doc{ID int; Base}` with `Base.ID json:"base_id"`). The grammar's objects are flat, and devalue addresses fields by GoName, so the shape cannot be carried without extending the grammar; HEAD's schema path rendered both properties, HEAD's strict path already refused it via Validate's duplicate-Go-name rule. New message: `promoted field Root.Base.ID shares Go field name "ID" with Root.ID at <pos>; a shadowed promoted field is outside the static type grammar`. Not extended further per user instruction (no scope upgrades).
decision: Codec-only roots (`Declare[T]()`, `GoJSON()`) now go through the same grammar as every other output, so fields HEAD's codec-only walk ignored (maps, bare pointers with omitempty, `[]byte`) are refused. This is the direct consequence of the issue's single-lowering design; flagged to the user rather than re-adding a lenient codec-only walk.
decision: Every lowering error is now wrapped `build type definitions for <pkg>.<T>: type <T> at <pos>: ...` (was `rendering struct field: ...`); Optional-without-omitzero names `Doc.O` instead of `o`. Types and positions unchanged.
doc_bug: README limitation said recursive pointer embedding fails "with a competing-MarshalJSON diagnostic" -> now says it is rejected as a bare pointer field.
