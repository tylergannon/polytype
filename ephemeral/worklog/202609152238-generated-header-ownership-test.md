# Generated-header ownership test

Task: close a mutation-testing gap — `generatedGoHeader` in
`internal/builder/gen_schema.go` was never compared against the header
`schemas.go.tmpl` emits, so changing either alone left `go test ./...` green.

decision: the pinning test lives in `internal/builder/render_go_code_test.go`,
beside the other pure `renderGoCode` tests, not in `basic_test.go`. The link
under test is template-output -> `ownedGeneratedFile`; neither side needs a
package load, so the test runs in milliseconds and stays in the cacheable
pure-render layer instead of the load-based acceptance layer.

decision: added negative controls (handwritten file, another tool's
`Code generated by` header, the header below the package clause, missing file)
alongside the positive case. `ownedGeneratedFile` had no direct test at all; a
lone positive assertion would still pass against a function that returned true
unconditionally, which is the same class of blind spot being fixed.

proof: mutated each side independently and confirmed the new test fails for
both, then restored.

- constant only (`DO NOT EDIT.` -> `DO NOT MODIFY.` in gen_schema.go) -> FAIL
- template only (same edit in schemas.go.tmpl) -> FAIL
- both restored -> `go test ./...`, `just lint`, `just build-tagged` all clean

friction: `assertGeneratedGoHeader` in `basic_test.go` held a third independent
copy of the header text. Consolidating it onto the constant was blocked by a
package boundary, not by oversight: `basic_test.go` is `package builder_test`
and both `generatedGoHeader` and `ownedGeneratedFile` are unexported, so the
literal was the only thing that file could assert. Resolved with the usual
`export_test.go` shim, which also let the load-based test run the real
generated artifact through `ownedGeneratedFile` -> if another external test
needs a builder internal, extend `export_test.go` rather than copying a value.
