# Material findings

- **High — `UnmarshalJSON` accepts JSON `null` when zero is a declared enum member.** In `internal/builder/schemas.go.tmpl:62`, the generated decoder unmarshals directly into the underlying string or integer before checking membership. `encoding/json` accepts `null` for either destination and leaves its zero value unchanged, so an enum containing `""` or `0` treats `null` as that member. I reproduced this with a marked `type Priority string` whose declared member is `Low Priority = ""`: `json.Unmarshal([]byte("null"), &priority)` returned nil and assigned `Low`. This contradicts the step's requirement that the decoder accept only a constant's own string/number wire value, and produces a value the emitted enum schema rejects.

- **High — Existing production JSON methods on a marked enum make generated packages fail to compile.** `internal/builder/gen_schema.go:1391` schedules every locally marked enum for codec emission, and `internal/builder/schemas.go.tmpl:50`/`:62` emits both methods without using the repository's existing production-method collision check. I reproduced generation for a marked `Priority` that already declares `MarshalJSON`; generation succeeded, then `go test` failed with `method Priority.MarshalJSON already declared`. This is a regression for a previously valid package and leaves the user with generated output that cannot build instead of a pre-write diagnostic.
