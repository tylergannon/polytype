# Material findings

- **Issue — The consumer test does not demonstrate the brief's validated-document round trip.** The brief requires a *validated* document to survive `json.Unmarshal`/`json.Marshal` byte-identically (`design-brief.md:52-56`), but `TestEnumCodecThroughStruct` only unmarshals and re-marshals the literal (`internal/builder/testfixtures/enums/enum_codec_test.go:78-98`). `EnumHolder` is not registered in `schema.go` and has no generated schema or `ValidateJSON` method (`internal/builder/testfixtures/enums/schema.go:11-31`), so this proof would remain green if the generated schema's enum set drifted from the generated codec. Register the enclosing struct for validation and validate the document before decoding it.

- **Issue — The zero-value failure does not name the failing field as required.** The brief says the zero-valued struct failure must name the field (`design-brief.md:52-55`), but the assertion accepts any error containing only `EnumType` and `""` (`internal/builder/testfixtures/enums/enum_codec_test.go:70-76`). The generated enum error itself contains only the enum type and value (`internal/builder/schemas.go.tmpl:50-57`), and `encoding/json` wraps a `MarshalJSON` error with the Go type rather than the enclosing `kind` field, so a consumer with multiple fields of this enum cannot tell which field failed. The proof needs to assert the field identity, and the implementation must preserve it through the enclosing struct's encode path.
