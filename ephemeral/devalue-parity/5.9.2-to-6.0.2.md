# devalue changes since the 5.9.2 parity capture (through 6.0.2)

Captured 2026-09-25. Pinned parity release: **5.9.2** (npm shasum
`2a3a8ad21904c6a630bf7bb160acb7ca2fa1e467`). Newer releases: 5.9.3 and 5.9.4
(2026-09-18), 6.0.0 (09-19), 6.0.1 (09-21), 6.0.2 (09-22, npm `latest`).

Which devalue do consumers run? SvelteKit 2.70.3 (`latest`) depends on
`devalue ^5.8.1`, and 3.0.0-next.29 on `^5.9.4`. Neither accepts 6.x yet.

## Method

1. Upstream GitHub release notes for each tag.
2. `diff -r` of the published npm tarballs (shasums checked against the registry).
3. The committed golden corpus (337 values) re-recorded against every release.
4. Targeted probes for behaviors the corpus does not cover, run on every
   release and, where Go can express the input, through `polytype/devalue`.

Corpus result: flat `stringify` output is **byte-identical in every release**.
`uneval` differs in 1 case under 5.9.x (`sparse_array`) and 3 under 6.0.x
(`sparse_array`, `shared_reference`, `self_cycle`).

## Change map

Go today = what `polytype/devalue` (pinned to 5.9.2) does for the same input.

### 5.9.3: security and performance fixes, no API change

| # | Area | Upstream change | Evidence (5.9.2 → new) | Go today | Parity work |
|---|------|-----------------|------------------------|----------|-------------|
| 1 | uneval | Repeated strings of ≥128 UTF-16 units and repeated BigInts are hoisted when that saves bytes (`len·count > len + (count+1)·name + 25`). Boxed String/BigInt now count their primitive. ### 6.0.0: breaking

| # | Area | Upstream change | Evidence | Go today | Parity work |
|---|------|-----------------|----------|----------|-------------|
| 9 | uneval API | **The replacer becomes `(value, js) => JavaScriptFragment \| false \| null \| undefined`.** `js` is a tagged template: literal parts are emitted verbatim, and interpolated values are serialized in the *same* namespace, so shared references and cycles through custom values now work. Identifiers in the literal text are reserved, so generated names never shadow them. Returning a string throws `TypeError` (afb3cb4). | a string replacer → `TypeError: Invalid JavaScript fragment` | `Replacer func(v, uneval func(any) (string, error)) (string, bool, error)`, where nested `uneval` has its own namespace (5.9.2 semantics) | New Go replacer API. This is a Go API change that affects skgo's transport encoders |
| 10 | uneval | Hoisting emits `(function(){let a=…;…;return X}())`. `let` declarations appear lazily in dependency order, replacing IIFE parameters and arguments. Names are assigned in the order values are first seen repeated, no longer sorted by count. A Map or Set starts as `new Map([[k,v],…])` with its ready prefix, then `.set(…)` for the rest. The primitive-hoisting overhead constant goes from 25 to 40. The 65534-parameter fallback is gone. | `(function(a){a.x=1;return [a,a]}({}))` → `(function(){let a={};a.x=1;return [a,a]}())`; `[x,x,y,y,y]` names swap | 5.9.2 shape | Rewrite the hoisting emitter. The `shared_reference` and `self_cycle` goldens change |
| 11 | stringify + uneval | `stringify_string` escapes unpaired surrogates as `\udXXX` (ac295fb) | `"a\ud800b"`: raw surrogate → `"a\ud800b"` escaped, in **flat** output too | Go strings cannot hold one: WTF-8 input writes three U+FFFD, and `Parse` of `"\ud800"` yields U+FFFD | Decide whether to map WTF-8 surrogate bytes to `\udXXX`; otherwise keep it as a documented model limit |
| 12 | runtime | Requires Node ≥ 22.17 | none | Affects only the recorder (CI uses Node 24) | None |

## Corpus gaps

The recorder's corpus cannot detect #1, #3, #9, #11, #13 or #14: it has no long
repeated strings or BigInts, no lone surrogates, no replacers, no malformed
documents, and no typed arrays (the flat format does not carry them). Any
upgrade should extend `devalue/testdata/record/main.go`, or the hand-ported
`uneval_test.go` cases, with those shapes before re-recording.

## Downstream impact: skgo

skgo (`/Users/tyler/src/skgo`, requires polytype v1.1.0) uses
`Parse`/`Stringify`/`StringifyWith`/`Reducer` heavily. It uses the `uneval` surface
in 3 files: 6 `UnevalWith` call sites, 4 uses of the `Replacer` type,
`Uneval` once and `QuoteString` twice (`transport.go`, `document.go`,
`document_assemble.go`). Its transport hook and `deferReplacer` mirror kit's
`get_replacer`, which is written against devalue 5's nested-`uneval`
replacer. skgo's contract is byte-for-byte parity with kit's output, and kit
renders with the devalue it resolves: `@sveltejs/kit@3.0.0-next.28` in
`example/web` resolves **devalue 5.9.4**.

| Change | Compile break in skgo | Output bytes skgo emits | skgo tests at risk |
|--------|-----------------------|-------------------------|--------------------|
| This branch (the pin) | None: one added constant | None | None (suite run below) |
| Parity 5.9.4 (#1–#3) | None: no API change | Change only for sparse arrays with holes and repeated ≥128-unit strings or BigInts. That moves skgo *toward* kit, which already emits the 5.9.4 forms | None found: no pinned expectation has a sparse array, long repeated string or BigInt. The flat wire goldens are unaffected |
| Parity 6.0.x (#9–#10) | **Yes, if `Replacer`/`UnevalWith` change in place.** That also breaks polytype's own v1 API, so it would need an additive API or `/v2` | Every hoisted expression changes shape, and skgo would diverge from kit until kit adopts devalue 6 | Hoisted shapes are not pinned in skgo's tests, but the kit-parity contract breaks regardless |
| Parity 6.0.x (#11, #13, #14) | None | Lone surrogates cannot occur in Go. #13 rejects payloads devalue never writes. #14 turns an error into output | None |

## Recommendation

The parity target that matters downstream is the devalue **kit resolves**,
not upstream's latest.

1. **Next pin: 5.9.4.** It is what kit renders with today, so it closes a
   gap in skgo's byte parity with kit. Its fixes are the upstream DoS
   protections for `uneval` output (#1–#3), and it changes no Go API. The work
   is #1–#3 plus the #8 doc note, then re-recording (only `sparse_array` moves
   on today's corpus).
2. **Hold 6.0.x until kit depends on `devalue ^6`.** Then ship it as a polytype
   minor release with an *additive* replacer API (#9), leaving `Replacer` and
   `UnevalWith` intact, so skgo compiles unchanged and switches when it mirrors
   kit's new `get_replacer`. #10 is the hoisting rewrite; #13 and #14 are
   small; #11 needs a decision.
