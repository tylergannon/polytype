# v1 Go/JSON contract

Status: accepted release contract, tracked by [#56](https://github.com/tylergannon/polytype/issues/56). Implementation and conformance remain release prerequisites. This document specifies the 1.0 target; it does not claim that a release candidate already implements every row.

The product promise is a supported Go value crossing the JSON boundary without losing its defined meaning. Schema generation, JSON encoding, JSON decoding, and validation are separate capabilities. A generated schema alone is not evidence of a working codec. [#62](https://github.com/tylergannon/polytype/issues/62) must demonstrate the complete supported matrix before release.

This contract supersedes the earlier draft's promises of blanket v0.5.3 compatibility, global enum adapters, scalar-only interface support, and post-v1 union/enum encoding. Current user guidance is in the [documentation website](../../website/src/content/docs/) and [installable skill](../../skills/polytype/SKILL.md).

**Amendment, 2026-09-05 (v1.0.0-rc.7, [#93](https://github.com/tylergannon/polytype/pull/93), issues [#86](https://github.com/tylergannon/polytype/issues/86)/[#87](https://github.com/tylergannon/polytype/issues/87)/[#88](https://github.com/tylergannon/polytype/issues/88)).** The union and enum contract was rewritten in place to match shipped semantics. Union membership is inferred from an interface's unexported sealing method; the discriminator wire value is always the concrete Go type name; the discriminator property defaults to `type` and is set once per interface with `polytype.SealedUnion[I](name)` in the interface's own package; enum-ness is inferred from a `func (T) enum()` marker, with `.StringerEnum` remaining the explicit field-level string-mode selection. The field-level `Impl(...)`/`Discriminator(...)` registrations, explicit wire values, and "legacy derived names" that earlier revisions of this document specified were removed along with `Declaration.Enum`, `Declaration.Interface`, `WithEnum`, `WithInterface`, `WithInterfaceImpls`, `WithDiscriminator`, `NewEnumType`, and `NewInterfaceImpl`. The current wording of the [enum guide](../../website/src/content/docs/features/enums.md) and the [sealed-interface guide](../../website/src/content/docs/features/interfaces.md) is authoritative where this document is silent.

**Amendment, 2026-09-06 ([#106](https://github.com/tylergannon/polytype/issues/106)).** Value-mode enum types declared in the generation target package now receive a generated type-level `MarshalJSON`/`UnmarshalJSON` pair that enforces membership in both directions, replacing this document's earlier claim that such enums cross the boundary under standard Go JSON with membership validated separately.

## Supported boundary and semantic equality

For a supported Go value satisfying its declared field constraints, JSON encoding must produce a document accepted by its generated schema. Decoding that document must preserve:

- scalar values and enum values;
- absent versus present-zero Optional values, and null versus present Nullable values;
- the inferred union variant, including whether the sealing method's receiver made it a value or pointer variant;
- array/slice order and nested field meaning.

For accepted JSON input, decode/encode/decode must preserve the same meaning. Accepted input means schema validation **and** decoding into the declared Go type both succeed. JSON Schema can admit numbers outside a particular Go integer's range; Go decoding must reject those values rather than truncate or wrap. Schema validation is not a substitute for successful typed decoding.

Equality does not include JSON whitespace/property order, Go pointer identity or shared allocation, time monotonic readings/location identity, or inactive wrapper payloads (`Present == false`). `time.Time` equality uses the represented instant; finite float equality uses the Go value, not preservation of numeric spelling or the sign of zero. Invalid UTF-8 Go strings are outside the lossless domain. Arbitrary-precision JSON numbers and non-finite floats are not portable Go scalar values under this contract.

Ordinary fields remain required and non-null. A nil pointer or nil slice that encodes as null is not a valid non-null field value. Non-nil empty slices encode as `[]`. An `omitempty` or `omitzero` tag that removes a required ordinary property puts that value outside the valid domain; the tool must diagnose this limitation instead of claiming such tags express schema optionality. Use Optional for absence and supported Nullable shapes for null.

The matrix is deliberately not a Cartesian-product promise. For example, supporting a scalar enum and a slice does not by itself establish field-specific string-mode conversion inside every possible container. String-mode integer adaptation supports only direct E, Optional[E], and Nullable[E] owner fields; generation rejects other adapted containers. Inspection must report unproved contexts as unsupported or unknown.

## Generated-method ownership

Enum-ness and union membership are properties of the type, not of a field: a named type with a `func (T) enum()` marker is an enum everywhere it appears, and a sealed interface's variants are the same-package named struct types that declare its unexported sealing method directly. The only field-level setting is `.StringerEnum` (string mode for an integer enum field); the only per-union setting is the discriminator property declared with `SealedUnion[I](name)`. Schema generation and both codec directions must still consume one resolved field configuration, including enum mode, the inferred variant set, the discriminator property and the concrete-type-name wire values. A containing struct receives one composed `MarshalJSON` and one composed `UnmarshalJSON` when its fields require adapters. Separate union and enum implementations must not generate competing methods. Ordinary fields retain Go JSON naming, nesting and custom-hook behavior within the declared supported domain. Bare `omitempty` and `omitzero` are outside that domain: omission is admitted only through direct `Optional[T]` with `json:",omitzero"`. A direct bare pointer field is also outside the domain; authors state nullability with `Nullable[T]` or absence with `Optional[T]`.

Use a value receiver for generated `MarshalJSON` so encoding either a struct value or its pointer has the same field-aware behavior. Decode methods use pointer receivers. Do not add a global marshaler to a union implementation or enum type merely because one owner uses a particular wire representation. Reject production handwritten owner-method collisions before any output is written. Existing handwritten methods on concrete union implementations may be invoked as nested encoders only under the object/discriminator rules below; this does not authorize overriding owner methods.

For example, a `Created` variant of the sealed interface `Event` has the wire value `"Created"` in every owner: `Request.Event` and `Audit.Event` both emit `{"type":"Created",...}`, and if `Event`'s package declares `SealedUnion[Event]("kind")` both emit `"kind"` instead. Neither owner can rename the wire value or choose a different property; there is no per-field or per-owner discriminator configuration, and no explicit wire value can replace the Go type name.

Generated owner decoders decode into a fresh temporary value and assign only after complete success. Success replaces the receiver; errors leave it unchanged, including when a later slice element fails. This guarantee covers generated owner/wrapper code, not arbitrary user-hook side effects. Ordinary types using `encoding/json` without a generated owner retain its normal semantics; callers needing replacement use a fresh destination.

The JSON projection's canonical encoder is Go 1.27 `encoding/json/v2`, whose default maps nil slices to empty JSON arrays recursively. Generated owner marshalers use v2 with `encoding/json.DefaultOptionsV1()` and `jsonv2.FormatNilSliceAsNull(false)`, preserving the prior v1 behavior except for that normalization even when invoked by a v1 caller. Handwritten nested `MarshalJSON` methods remain authoritative and therefore outside the inferred slice guarantee.

Validation and decoding remain separate entry points. Generated decoding is not a blanket substitute for required-field, unknown-field or enum-membership validation. Call validation first when accepting external documents under the schema contract.

## Union decisions for #57

- Support scalar `I`, `Optional[I]`, and direct `[]I` for sealed interfaces. Variants are inferred, never declared: every same-package named struct type that declares the sealing method directly, where a value receiver makes a value variant and a pointer receiver a pointer variant. Preserve the variant's pointer/value kind on decode. A dynamic type that is not an inferred variant is an error even if it satisfies the interface, including a type that inherits the sealing method through an embedded field.
- The concrete Go type name is the sole wire identity; there are no explicit wire strings. Renaming a variant type changes its wire value, and adding or removing a qualifying implementation changes union membership; both are consumer-visible contract changes that surface as diffs in generated schema and TypeScript and require consumer migration. Go forbids two same-package types with one name, so derived-name collisions cannot arise. Every field of `I` resolves through the same type-level mapping, and decoder helper reuse is keyed by the interface together with its discriminator property, not the interface name alone.
- Concrete payloads must encode as JSON objects. Inject a missing discriminator. Preserve an already present discriminator only if its value is the variant's type name. Reject a conflicting/non-string discriminator, null or non-object payload; do not silently overwrite it.
- Reject nil interfaces and typed-nil implementations for required union values and slice elements. An absent Optional is omitted; a present Optional containing nil is an error. A nil `[]I` is not a valid required array and encoding must return an actionable error; an allocated empty slice emits `[]`.
- Single-implementation unions still carry the discriminator. Property names and discriminator values use JSON escaping.
- The discriminator property defaults to `type` and is set once per interface with `SealedUnion[I](name)` in the build-tagged file of the interface's own package, with a string-literal, nonempty property name. A declaration in another package, a duplicate declaration, a declaration for a non-sealed interface or a non-interface type, a non-literal argument, an invalid property name, or a variant payload property colliding with the discriminator property is a generation error naming the interface. Also rejected, with a diagnostic naming the type or field: a reachable interface field whose interface declares no unexported method of its own (non-sealed unions have no explicit fallback), an interface whose unexported method arrives only by embedding another interface, a direct declarer that is not a struct or does not implement the complete interface, a sealed interface with zero variants, and an embedded interface payload. Variants behind other build tags are not discovered; the scanner loads with the `jsonschema` tag. The three supported interface forms are a closed set, not examples of a broader family. Parenthesized/pointer forms and union fields reaching through inline/nested containers are excluded; declare a supported named owner at the level where its union field is declared. Supported promoted fields must follow Go field-selection/shadowing rules, with explicit #62 evidence rather than assumed coverage. An owner embedding another generated codec owner is rejected because promoted JSON methods would compete; use a named field for that nesting. #62 must also cover mixed enum/union owners, supported nesting, custom object payloads and both pointer/value call sites.

### Concrete custom-hook boundaries

For a variant `Created` of a sealed interface under the default discriminator `type` (wire value `"Created"`):

| Situation | Outcome and failure stage |
| --- | --- |
| Owner already has a production `MarshalJSON` or `UnmarshalJSON` that the generator needs to own | Generation-time collision error before any artifacts are written. A declaration stub in the mutually exclusive generation build is not a collision. |
| `Created.MarshalJSON` returns `{"name":"first"}` | Runtime encoding accepts the object and adds `"type":"Created"`. |
| It returns `{"type":"Created","name":"first"}` | Runtime encoding accepts and preserves the matching discriminator. |
| It returns `{"type":"Deleted"}` or `{"type":3}` | Runtime encoding rejects the conflicting/non-string discriminator. |
| It returns a string, array, `null`, or malformed JSON | Runtime encoding returns an error; no object payload is emitted. Hook output is not generally decidable during generation. |
| `Created.UnmarshalJSON` rejects the object containing `"type":"Created"` | Runtime decode returns that error without assigning the generated owner. Concrete hooks receive the complete discriminated object; the generator does not strip the discriminator to accommodate a hook. |

A nested ordinary custom hook that changes its schema's value kind is not made compatible by wrapping it in a generated owner. If incompatibility is evident from declaration/method ownership, generation rejects it; otherwise its claimed support requires explicit schema/roundtrip evidence. The tool must report unproved arbitrary hook transformations as unknown, not infer validity by executing user hooks during inspection.

## Enum decisions for #58

A named type is an enum when it declares the marker method `func (T) enum()` in ordinary, non-build-tagged Go; its values are the typed constants declared in the same package, and no field-level enum declaration exists. The marker must be exactly that shape: a pointer receiver, parameters, or results on a method named `enum` is a generation error naming the type, as is a marked type with no typed constants. The marker means value mode; a `String()` method on a marked type is ignored. Generation writes `var _ interface{ enum() } = <FirstConstant>` for every marked type in the package, referencing its first typed constant, so the marker is used from production code and its shape is compiler-checked without lint directives; a package that declares a marked enum but never runs generation needs that line written by hand. `.StringerEnum(field)` remains the explicit, field-level selection of string mode for an integer enum field, marked or not.

Numeric mode uses underlying constant values. String mode uses declared constant names, never the output of `String()`. One Go type may appear in two owners or fields with different modes; each field follows its `.StringerEnum` setting.

For string mode, unknown wire strings and underlying values without a registered name are errors, including an undeclared zero. Duplicate underlying values with different wire names are ambiguous for encoding: reject that string-mode field before writing output, rather than choosing an unstable canonical name. Numeric/string-value modes may deduplicate identical enum values without changing their meaning. Keep one canonical constant identifier per value for string mode, or retain numeric mode. Renaming a constant changes its string-mode wire value. The ApplicationConfig example uses string mode; Task intentionally remains numeric.

Optional absence and Nullable null bypass enum value conversion; present values use the field's enum mapping. Handwritten owner-codec collisions are errors. Per-field enum adapters must not silently bypass incompatible nested custom hooks; unsupported combinations require an explicit generation diagnostic.

## Manual helper decisions for #59

`Strict == true` means all declared object properties are required and `additionalProperties` is false in both `JSONSchema` and `ObjectSchema`. It overrides explicit Required/AdditionalProperties settings; non-strict mode preserves them. Map-backed properties/derived required keys have sorted order; slice-backed object properties retain insertion order. Repeated encoding of the same schema is byte-stable.

`ConstSchema` and `EnumSchema` classify named integer/string values by their underlying kind. Legal JSON property names are escaped. `EnumSchema` retains its `SchemaNode` return signature; an empty enum returns a node whose `MarshalJSON` reports a descriptive error. It must not panic during construction or produce an invalid/permissive schema.

## YAML boundary

YAML input and output are outside the generated v1 contract. An application
that accepts YAML must convert it to the JSON data model itself, then use
generated `ValidateJSON` and JSON codecs. JSON property names remain canonical.

Removing retained provider APIs after 1.0 requires a major release. #63 must preserve working provider behavior while removing the separate unfinished Tool/BuildTool experiment.

## Compatibility and release gates

Go 1.27+ and module mode are the current baseline. #66 must declare and test the supported platform/toolchain matrix before release; one machine does not establish universal portability.

Within 1.x, preserve supported exported Go APIs, registration and marker meaning, generated method signatures/ownership, documented CLI flags, versioned machine-result fields, and the meaning of accepted wire values. Adding optional machine fields is allowed only where the result contract permits unknown fields. Removing supported fields/methods or changing established discriminator/enum representations requires a major release. Tightening rejection of inputs already outside the documented valid domain is a bug fix, not a new supported-input guarantee. The minimum Go version may increase in a minor release with an explicit release note and a tested support matrix; patch releases do not raise it. Dependency upgrades must preserve supported wire behavior, and changes to dependency types exposed in public signatures require compatibility review.

Generated source text, checksums and formatting are not an ABI. Their meaning and deterministic regeneration are contractual; upgrades may produce reviewed generated diffs. Provider/user hooks can be stateful, so deterministic output is promised only for the same deterministic inputs and hook results. A valid JSON Schema is not evidence of acceptance by every model provider's restricted schema dialect.

#60 publishes the installed binary's version/capabilities and structured diagnostic contract. #61 supplies read-only complete-artifact preview using the same rendering operations as generation. #63 removes unfinished product surfaces and stale claims. #64 packages the version-aware plugin. #65 proves real-agent workflows using artifact graders. #66 binds conformance, agent evidence and installation proof to the exact release candidate. App-server assistance, streaming helpers, arbitrary schema-to-Go generation and broader Go shapes remain outside 1.0.
